# ระบบลงรับหนังสือราชการ

โรงเรียนบ้านโพนทองประชาอุทิศ · สพป.สกลนคร เขต ๑

ระบบช่วยลงรับหนังสือราชการ ใช้ได้ทั้งบนคอมและมือถือ

## ความสามารถ

| โหมด | ทำอะไร |
|---|---|
| ๑ | ดึงหนังสือใหม่จากเว็บ สพป. → AI อ่านและเกษียณ → ลงตรายาง → ส่งเข้ากลุ่ม LINE |
| ๒ | อัปโหลด PDF/รูปเอง แล้วให้ AI เกษียณให้ |
| ๓ | ลงตรายางเลขรับบนกระดาษ A4 เปล่า ไว้ปริ้นทับเอกสารที่ส่งมาเป็นกระดาษ |

พร้อมหน้าถอยเลขรับเวลาลงผิด และระบบผู้ใช้หลายคนแบบต้องอนุมัติก่อน

**รายการโหมด ๑ เปิดมาที่ "ยังไม่ลงรับ" เสมอ** — เห็นแต่เรื่องที่ค้างอยู่ กด ทั้งหมด / รับแล้ว / ข้าม ดูเรื่องอื่นได้
กลับมาหน้านี้อีก (ลงรับเสร็จ / เปิดใหม่) ก็เริ่มที่ยังไม่ลงรับ วันที่ที่เลือกไว้ยังจำอยู่ ลงรับครบแล้วขึ้นบอกว่าไม่มีเรื่องค้าง

**🤖 ให้ AI อ่านใหม่** — AI อ่านหนังสือไม่สำเร็จ (Google ไม่ว่าง / รุ่นที่ใช้ถูกปิด / โควต้าหมด) หน้าจัดเอกสาร
ขึ้นแถบแดงบอกเหตุพร้อมปุ่มนี้ กดแล้วส่งไฟล์เดิมให้อ่านใหม่ทั้งเรื่อง (คำเกษียณ หน้าที่มีลายเซ็น ตรวจบรรทัด "เรียน")
อ่านแล้วไม่ตรงเรื่องก็กดได้จากแผง ✏️ แก้คำเกษียณ (ตำแหน่งที่จัดไว้เริ่มใหม่) · รุ่น AI ที่ Google ปิดไปแล้ว
ระบบข้ามไปใช้รุ่นถัดไปเอง ดูหัวข้อ `SARABAN_GEMINI_MODEL` ด้านล่าง

**เลขรับที่จะลง** บนหน้าจัดเอกสารเป็นเลขจริงเสมอ — เปิดเรื่องค้างไว้แล้วไปลงเรื่องอื่นก่อน กลับมาที่หน้านั้น
(หรือเปิดใหม่) เลขกับตรายางตัวอย่างเปลี่ยนเป็นเลขถัดไปให้เอง ตอนบันทึกได้เลขที่ถูกต้องอยู่แล้ว

**ลงรับผิด → ♻️ ลงรับใหม่ (ใช้เลขเดิม)** — เรื่องที่ลงรับแล้วยังอยู่ในรายการโหมด ๑ กดปุ่มนี้
เปิดเรื่องเดิมให้ AI อ่านใหม่ จัดใหม่แล้วบันทึก ได้เลขรับเดิม เขียนทับแถวเดิมในทะเบียน (ไม่กินเลขใหม่)
ข้อความ LINE ใหม่ขึ้นต้นว่า "♻️ ลงรับใหม่ (แก้ไข)" ให้กลุ่มรู้ว่าใช้แทนข้อความก่อน ไฟล์ครั้งก่อนในไดร์ฟยังอยู่
ลบเองได้ ปุ่มล่างซ้ายกลายเป็น **↩️ ยกเลิก** — กดแล้วเรื่องยังลงรับไว้เหมือนเดิม ไม่ถูกจดว่าข้าม

**คิวจากมือถือสำรองไว้ ๗ วัน** — เรื่องที่ออกจากคิวแล้ว (ลงรับหรือข้าม) เซิร์ฟเวอร์เก็บต้นฉบับไว้บนไดร์ฟ
อีก ๗ วัน ยังอยู่ในรายการโหมด ๑ ลงรับใหม่ได้โดยไม่ต้องให้มือถือดึงมาใหม่ (บน Render ดึงจากเว็บ สพป. เองไม่ได้)
- ลงรับผิด → ♻️ ลงรับใหม่ (เลขเดิม) ตามข้างบน
- ข้ามผิด → เรื่องยังขึ้นว่า "ข้าม" กด **📥 ลงรับเรื่องนี้** ได้ (เดิมข้ามแล้วหาย และลงรับไม่ได้อีกเลย)
- ลบเรื่อง (หน้า 🔧 กด 🗑 ถอยเลข) → เรื่องนั้นกลับไปเป็น "ยังไม่ลงรับ" เอง ไม่ต้องพิมพ์เลข ID ที่ช่องล่างแล้ว
  ถ้าเป็นเลขล่าสุด ลงรับใหม่ได้เลขเดิม · หนังสือฉบับเดียวกันยังมีอีกแถว (เคยลงซ้ำ) ถือว่ายังลงรับอยู่

ตั้งจำนวนวันด้วย `SARABAN_REDO_DAYS` (`0` = ลบทันทีแบบเดิม) เรื่องที่จบก่อนมีระบบนี้ หรือเกินกำหนดแล้ว:
ถอยเลขแล้วรัน `phone_fetch.py` ให้มือถือดึงมาส่งใหม่ (เดิมเซิร์ฟเวอร์ตอบมือถือว่า "จัดการไปแล้วโดยอีกเครื่อง"
จนกว่าจะรีสตาร์ท) หรือลงรับใหม่จากเว็บที่คอมโรงเรียน (`เปิดเซิร์ฟเวอร์.bat` — ดึงจากเว็บ สพป. ได้)
หรือโหมด ๒ อัปไฟล์ต้นฉบับ แล้วใส่เลขเดิมในช่อง "ลงรับใหม่ด้วยเลขเดิม"

หนังสือที่แยกไฟล์แนบหลายไฟล์ (หนังสือนำ + บัญชีรายชื่อ ฯลฯ) รวมเป็นเล่มเดียว หน้าจอเห็นครบทุกหน้า
ไฟล์ที่บันทึกมีสิ่งที่ส่งมาด้วยครบ (เฉพาะไฟล์ PDF — รูป/Word/Excel เป็นลิงก์ในข้อความ LINE)
**ไฟล์ที่ชื่อมีคำว่า "หนังสือราชการ" ขึ้นหน้าแรกเสมอ** — เว็บ สพป. บางเรื่องวางไว้ลำดับที่ ๓
(๑.–๒. สิ่งที่ส่งมาด้วย ๓. หนังสือราชการ+สิ่งที่ส่งมาด้วย) เดิมหน้าแรกเลยเป็นสิ่งที่ส่งมาด้วย AI อ่านผิดฉบับ
ไฟล์อื่นต่อท้ายตามลำดับบนเว็บ ไม่มีไฟล์ชื่อนี้ใช้ PDF ไฟล์แรกเหมือนเดิม (ข้อความ LINE ยังเรียงลิงก์ตามเว็บ)
เรื่องจากมือถือ มือถือเป็นคนเลือกไฟล์ — ต้องก๊อป `sppweb.py` ชุดใหม่ไปมือถือด้วย
ไฟล์แนบ PDF ที่ไม่ได้มาด้วย หน้าจัดเอกสารขึ้นเตือนว่ากี่ไฟล์ — ส่วนใหญ่เพราะมือถือยังใช้สคริปต์รุ่นก่อน
(ส่งแค่หนังสือนำ) อัปเดต `phone_fetch.py` `core.py` `sppweb.py` ในมือถือ เรื่องที่ดึงหลังจากนั้นจะมีครบ
เรื่องที่ค้างคิวมาก่อนอัปเดต (หรือโหลดไฟล์แนบไม่สำเร็จ) กด **🔄 ดึงเรื่องนี้ใหม่พร้อมไฟล์แนบ** ใต้คำเตือน
แล้วรัน `phone_fetch.py` — ปกติมือถือไม่ดึงเรื่องที่อยู่ในคิวแล้วซ้ำ เรื่องที่กดไว้มือถือจะดึงมาส่งใหม่
(ลงรับใหม่ ♻️ อยู่ก็ดึงให้ ได้เลขเดิมเหมือนเดิม) เซิร์ฟเวอร์ใส่ไฟล์ใหม่แทนในงานเดิม ไฟล์เก่าบนไดร์ฟลบให้
หน้าจัดเอกสารที่เปิดค้างไว้รู้เองแล้วบอกให้โหลดใหม่ คำเกษียณที่จัดไว้ใส่คืนให้ ระหว่างรอยังบันทึกแบบเดิมได้
รายการโหมด ๑ ขึ้นบอกว่าเรื่องไหนรอมือถืออยู่ · เว็บที่เปิดบนคอม (ต่อเว็บ สพป. ได้) ปุ่มเดียวกันดึงจากเว็บ สพป. ใหม่เลย
ส่ง LINE ตั้งต้นถึงหน้าที่มีลายเซ็นผู้ส่ง หน้าอื่นติ๊กส่งเองบนหน้านั้น

ภาพหน้าสิ่งที่ส่งมาด้วย (ทุกหน้านอกจากหน้าแรกกับหน้าที่มีลายเซ็น) ดึงจากเซิร์ฟเวอร์ทีละ ๒ หน้าตอนเลื่อนไปใกล้ถึง
ระหว่างดึงบนหน้าขึ้นว่ากำลังดึง ไม่สำเร็จลองเองอีกรอบ แล้วขึ้น **🔄 ดึงหน้านี้ใหม่** /
**🔄 ดึงใหม่ทุกหน้าที่ไม่ขึ้น** บนหน้านั้น (เดิมเป็นหน้าขาวเฉยๆ ต้องโหลดทั้งหน้าใหม่ สิ่งที่จัดไว้หายหมด)
ดึงใหม่แล้วสิ่งที่จัดไว้ยังอยู่ครบ — ภาพไม่ขึ้นไม่เกี่ยวกับไฟล์ที่บันทึก ซึ่งมีทุกหน้าครบเสมอ
ถ้าเซิร์ฟเวอร์เพิ่งเริ่มใหม่ (เรื่องที่เปิดค้างไว้หาย) ขึ้นบอกด้านบนเลยไม่ต้องรอกดบันทึก — เก็บสิ่งที่จัดไว้ให้
กด 🔄 โหลดเรื่องนี้ใหม่ แล้วใส่คืนให้เอง

หน้ากระดาษเปล่าไว้ลงคำเกษียณไม่แสดงไว้ก่อนแล้ว — ข้างลายเซ็นไม่มีที่ กด **➕ แทรกหน้ากระดาษเปล่า**
(หน้าเว็บอยู่ใต้หน้าที่มีลายเซ็น โปรแกรมบนคอมอยู่บนหัวหน้านั้น) หน้าเปล่าแทรกต่อจากหน้าที่มีลายเซ็น
ลากคำเกษียณไปวางได้ แทรกแล้วอยู่ในไฟล์ด้วยแม้ไม่ได้วางอะไร ไม่ใช้กด **✕ เอาหน้านี้ออก**

**ไฮไลท์ชื่อโรงเรียน** — ระบบหาชื่อโรงเรียนในหนังสือ เช่น บัญชีรายชื่อแนบท้าย แล้วป้ายสีเหลือง
เหมือนปากกาเน้นข้อความ ทั้งในไฟล์ PDF และรูปที่ส่ง LINE
เปิด/ปิดได้ในหน้าจัดเอกสาร (ทั้งเรื่องหรือทีละหน้า) ส่วนเมนู 👤 → 🖍️ ไฮไลท์ชื่อโรงเรียน ตั้งให้ไฮไลท์เอง
ตั้งแต่เปิดเรื่อง (เก็บกับบัญชี) — หาจากตัวหนังสือในไฟล์ทุกหน้าตอนเปิดเรื่อง

หน้าที่เป็นภาพสแกนไม่มีตัวหนังสือให้ค้น — กดปุ่ม **🔎 สแกน** ล่างจอ (ข้างปุ่มบันทึก มีเฉพาะเรื่องที่มีหน้าสแกน)
เลือกหน้า … ถึง … (ปกติคือหน้าบัญชีรายชื่อ) เซิร์ฟเวอร์อ่านภาพด้วย Tesseract ทำเบื้องหลัง
ไม่ใช้ AI ไม่กินโควตา แต่ช้า (Render ฟรีหน้าละราว ๑๕ วินาที ครั้งละไม่เกิน ๓๐ หน้า)
เจอชื่อแล้วไฮไลท์หน้านั้นให้ ส่ง LINE ยังติ๊กเอง — ชื่อที่ขึ้นบรรทัดใหม่กลางชื่อ หรือภาพไม่ชัดมาก อาจหาไม่เจอ
Dockerfile ลง `tesseract-ocr-tha` ไว้แล้ว — ไม่มีตัวอ่านภาพก็แค่สแกนไม่ได้ หน้าจอบอกไว้

ข้างปุ่ม 🔎 สแกน มีปุ่ม **✍️ แทรกลายเซ็น** (ทุกเรื่อง) — กดแล้ววางลายเซ็นผู้ลงรับพร้อมวันที่ใต้คำเกษียณเลย
ไม่ต้องเลื่อนขึ้นไปกางแผง ✍️ ลายเซ็น แทรกแล้วปุ่มกลายเป็น **✕ เอาลายเซ็นออก** ยังไม่มีรูปลายเซ็น
กดแล้วพาไปที่แผงให้เลือกรูป (เลือกแล้วแทรกให้เอง) ปรับขนาดยังทำในแผงลายเซ็นเหมือนเดิม
จอแคบปุ่มไม่พอในแถวเดียว ปุ่มบันทึกขึ้นแถวล่างเต็มความกว้าง

**บนคอมสแกนทั้งเรื่องเอง** — คอมอ่านภาพเร็ว (หน้าละ ~๑–๒ วินาที อ่านพร้อมกันหลายหน้าตามจำนวนคอร์)
โปรแกรมบนคอม (bot3) หาชื่อตอนเปิดเรื่อง แล้วสแกนหน้าภาพทุกหน้าเบื้องหลังเลย ไม่ต้องกดอะไร
หน้าที่พบชื่อไฮไลท์ให้ เปิด/ปิดที่ปุ่ม ✓ ไฮไลท์ บนหัวหน้านั้น ความคืบหน้า/ผลบอกใต้ชุดปรับแต่งด้านขวา
เว็บที่เปิดด้วย `เปิดเซิร์ฟเวอร์.bat` ก็สแกนทุกหน้าเองเหมือนกัน (`SARABAN_OCR_AUTO=1`)
ต้องลง Tesseract ภาษาไทยในคอมก่อน: ตัวติดตั้งของ UB Mannheim (github.com/UB-Mannheim/tesseract/wiki)
ตอนติดตั้งกาง Additional language data แล้วติ๊ก Thai — ลงที่ที่ตัวติดตั้งเสนอ โปรแกรมหาเจอเอง
(ลงไว้ที่อื่นบอกที่อยู่ `tesseract.exe` ด้วยตัวแปร `SARABAN_TESSERACT`) ลงแล้วไม่ต้องปิดเปิดโปรแกรมใหม่

## ตัวแปรระบบที่ต้องตั้ง

### จำเป็น

| ชื่อ | คืออะไร |
|---|---|
| `SARABAN_STORE` | ใส่ `sheets` (บน hosting ดิสก์ถูกล้างทุกครั้งที่รีสตาร์ท) |
| `SARABAN_SHEET_ID` | รหัสสเปรดชีต (เอาจาก URL) |
| `SARABAN_SA_JSON` | เนื้อไฟล์กุญแจ service account ทั้งก้อน |
| `SARABAN_WORK` | ใส่ `/tmp` — ที่เขียนไฟล์ชั่วคราว |
| `SARABAN_OUTPUT` | ใส่ `/tmp/out` — ที่พักไฟล์ PDF ก่อนส่งขึ้น Drive |
| `SARABAN_GEMINI_API_KEY` | กุญแจ Gemini (AI อ่านหนังสือ) |

> **รุ่นของ AI** — ไม่ต้องตั้ง ระบบลองตามลำดับ `gemini-flash-latest` (ชื่อกลางที่ Google ชี้ไปรุ่น Flash
> ล่าสุดให้เอง) → `gemini-2.5-flash` ถูกปิดหมดก็ถาม Google ว่ามีรุ่น Flash ไหนเหลือแล้วใช้รุ่นใหม่สุด
> Google ไม่ว่าง (503) รอแล้วลองซ้ำ ยังไม่ว่างก็ลองรุ่นถัดไป · จะกำหนดเองตั้ง `SARABAN_GEMINI_MODEL`
> (คั่นด้วย `,` ได้หลายรุ่น ลองก่อนลำดับข้างบน) รุ่นที่ใช้ได้จริงดูใน log ของ Render: `AI อ่านหนังสือด้วยรุ่น ...`
| `SARABAN_LOGIN_USER` / `SARABAN_LOGIN_PASS` | รหัสเข้าเว็บ สพป. |

### ถ้าจะให้ส่ง LINE

`SARABAN_LINE_ACCESS_TOKEN` · `SARABAN_LINE_GROUP_ID` · `SARABAN_IMGBB_API_KEY`

รูปหน้าเอกสารที่ส่งเข้า LINE เก็บไว้คู่กับไฟล์ PDF เสมอ ในโฟลเดอร์ย่อย `รูปที่ส่ง LINE` ของวันนั้น
(ชื่อตามไฟล์ PDF ต่อด้วยเลขหน้า เช่น `เลขรับ_๕๗_ศธ 1_หน้า๒.jpg`) ทั้งหน้าเว็บและโปรแกรมบนคอม
โฟลเดอร์วันจึงเห็นแค่ PDF เรื่องละไฟล์ — ทั้งสองทางเก็บที่ `ปี/เดือน/วัน` เดียวกัน

คอมที่ Drive for Desktop ซิงก์ `C:\แฟ้มเสนอ_ผอ` และมีกุญแจไดร์ฟใน config.json: เปิดเรื่องแล้วโปรแกรม
ให้ไดร์ฟสร้างโฟลเดอร์ของวันนั้นก่อน (รอซิงก์ลงมาไม่เกิน ๒๐ วินาทีตอนบันทึก) ไม่สร้างในเครื่องเอง
เพราะกุญแจของเซิร์ฟเวอร์ (สิทธิ์ drive.file) มองไม่เห็นโฟลเดอร์ที่คอมสร้าง แล้วจะสร้างชื่อเดียวกันซ้อนอีกอัน
(ไดร์ฟเคยมี `๒๕๖๙` สองอัน) — ดูว่าซิงก์อยู่จากโฟลเดอร์ `คิวรอลงรับ` ที่ซิงก์ลงมาอยู่ในเครื่อง

บน hosting รูปไม่ผ่าน imgbb (imgbb บล็อก IP ศูนย์ข้อมูล) LINE มาดึงจากเซิร์ฟเวอร์เราเอง
เซิร์ฟเวอร์หลับแล้วตื่นหรือ deploy ใหม่ ก็หารูปคู่กับ PDF บนไดร์ฟมาให้ รูปในแชตจึงยังกดเปิดได้
(ต้องเปิดใช้ไดร์ฟไว้ — ดูหัวข้อเก็บไฟล์ PDF ถาวรด้านล่าง ไม่งั้นรูปจะหมดอายุทุกครั้งที่เริ่มใหม่)

### กุญแจคุกกี้ล็อกอิน (ไม่ตั้งก็ได้)

`SARABAN_SESSION_SECRET` — ข้อความลับยาวๆ อะไรก็ได้ ไว้เซ็นคุกกี้ล็อกอิน
ไม่ตั้งไว้ระบบจะแปลงจาก `SARABAN_SA_JSON` (หรือความลับตัวอื่นที่ตั้งไว้แล้ว) ให้เอง
เซิร์ฟเวอร์เริ่มใหม่กี่รอบ ผู้ใช้ก็ไม่หลุดจากระบบ (คุกกี้มีอายุ ๑๒ ชั่วโมง)
เปลี่ยนค่านี้เมื่อไร ทุกคนต้องล็อกอินใหม่

### ปรับการยิงเว็บ สพป. (ไม่ตั้งก็ได้)

| ชื่อ | คืออะไร | ค่าเริ่มต้น |
|---|---|---|
| `SARABAN_REQUEST_GAP` | เว้นจังหวะระหว่าง request กี่วินาที — กัน rate limit | `0.7` |
| `SARABAN_USER_AGENT` | User-Agent ที่ใช้ยิง ควรตรงกับ Chrome เวอร์ชันที่ใช้จริง | Chrome รุ่นล่าสุดที่ตั้งไว้ในโค้ด |
| `SARABAN_MAX_DOWNLOAD_MB` | ขนาดไฟล์แนบสูงสุดที่ยอมโหลด | `80` |

> เช็กว่าเน็ตเส้นที่ใช้อยู่เข้าเว็บ สพป. ได้ไหม: `python check_access.py`

### ถ้าจะให้เก็บไฟล์ PDF ถาวร

`SARABAN_DRIVE_UPLOAD=on` · `SARABAN_DRIVE_FOLDER=<รหัสโฟลเดอร์>` · `SARABAN_DRIVE_URL=<ลิงก์โฟลเดอร์>`
· `SARABAN_DRIVE_OAUTH=<JSON บรรทัดเดียว>`

> **service account อัปไฟล์ขึ้น Drive ไม่ได้อีกแล้ว** Google เลิกให้พื้นที่เก็บกับมัน
> สร้างโฟลเดอร์ได้ (โฟลเดอร์ไม่กินพื้นที่) แต่พออัปไฟล์จริงจะได้ 403
> `Service Accounts do not have storage quota` เสมอ — และเดิมโค้ดกลืน error นี้ทิ้ง
> จึงเห็นแค่โฟลเดอร์เปล่าโดยไม่มีอะไรบอก
>
> ทางแก้: ใช้สิทธิ์ของบัญชี Google คนจริง ไฟล์จะไปอยู่ในพื้นที่ ๑๕ GB ของบัญชีนั้น
> ขอสิทธิ์ครั้งเดียวด้วย `python setup_drive_oauth.py` แล้วเอาค่าที่ได้ไปใส่
> `SARABAN_DRIVE_OAUTH` (ในสคริปต์มีขั้นตอนตั้งค่าฝั่ง Google Cloud Console ครบ)
>
> ทดสอบว่าอัปได้จริงไหม: `python -c "import drive; print(drive.probe())"`

## พิมพ์ทะเบียนรับ/ทะเบียนส่ง

```bash
python printfmt.py
```

ได้ **ไฟล์ PDF พร้อมพิมพ์** ไว้ใน `SARABAN_OUTPUT` (เครื่องนี้คือ `C:\แฟ้มเสนอ_ผอ`)
A4 แนวนอน · TH Sarabun New ขนาด ๑๖ · หัวตารางซ้ำทุกหน้า · เลขหน้า
และที่สำคัญคือ **ขึ้นบรรทัดใหม่ที่ขอบคำ ไม่ตัดกลางคำ**

> ข้อนี้เป็นเหตุผลที่ต้องวาด PDF เอง — ภาษาไทยเขียนติดกันไม่มีเว้นวรรค
> กูเกิลจึงตัดบรรทัดตรงไหนก็ได้ ("เลขทะเบี/ยนรับ") และสั่งให้ตัดตามคำไม่ได้เลย
> ที่นี่ใช้ตัวตัดคำไทยตัวเดียวกับที่ใช้พิมพ์คำเกษียณ (`thaiwords`)

พร้อมกันนั้นก็จัดหน้าชีตบน Google Sheets ให้อ่านง่าย แปลงเลขในทะเบียนเป็นเลขไทย
ทั้งแผ่น (สำรองของเดิมเป็น `.json` ก่อนแก้เสมอ) และให้ลิงก์สั่งพิมพ์ของกูเกิลไว้
เปิดดูจากมือถือ — สั่งครั้งเดียวพอ แถวที่ลงรับใหม่และแท็บปีถัดไปได้รูปแบบเดียวกันเอง

| คำสั่ง | ได้อะไร |
|---|---|
| `python printfmt.py` | ครบทุกอย่าง |
| `python printfmt.py pdf` | เอาแค่ไฟล์ PDF ไม่แตะชีต |
| `python printfmt.py links` | เอาแค่ลิงก์สั่งพิมพ์ของกูเกิล |
